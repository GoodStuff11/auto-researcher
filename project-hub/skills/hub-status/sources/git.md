# Code repositories and Overleaf
## Configuration
`project.yaml` `sources.repos: [{root: <ROOT>, branch: <name>}]`, `sources.overleaf: {root: <ROOT>, branch: <name>}`; each `<ROOT>` is a key of `roots`, with this machine's path in `hub.local.yaml` `roots`. Watermark `git.<ROOT>` = newest ingested commit.
## Steps (per root)
1. `git -C <path> fetch` then fast-forward the configured branch if it is a clean clone you own (for Overleaf: `git -C <path> pull`). If the path is missing on this machine, `hub ingest git` says so: report the root as not reachable.
2. `hub ingest git <ROOT>` → JSON commits since the watermark (a `warning` means history was rewritten, or that the list was cut short; see step 5; mention it).
3. Group commits by topic (same files / same subject prefix). Per group write one `safe` `log` line, source `commit:<ROOT>@<short sha of the newest commit in the group>`: what changed and why it matters ("Trotter optimizer: warm starts resume in their own gate order (3 commits)"). For Overleaf, name who edited which section ("Tamra: rewrote ¶2 and Fig. 1 caption").
4. Where a commit clearly serves an item (its message names the item id, or it finishes the work an action describes), add a `safe` `entry` on that item. A commit that appears to finish an action or answer a question → a proposal to close it, never a direct close: ops `{op: set, id, fields: {status: done|answered|dropped, closed: "<YYYY-MM-DD>"}}` plus a closing `{op: entry, id, text, source}` (an action closes with `done`; see the closure example in `sources/circleback.md`).
5. `hub ingest batch "$SCRATCH/<file>"` (batch files live in the scratch directory), then, only if it succeeded, `hub ingest git <ROOT> --advance --to <full sha of the newest commit you recorded>` (the last `sha` of the list from step 2). `--to` stops the watermark at what you recorded, so a commit pushed while you were writing is listed next time instead of skipped; if it says the sha is not listed, re-run step 2 and record the new commits first. Then `hub commit "status: git.<ROOT> (<YYYY-MM-DD>)"` (SKILL.md, update step 3). `hub ingest git` lists at most `--limit` (default 500) of the OLDEST unlisted commits. If its warning contains "not listed yet", record the batch, run `--advance --to <newest recorded sha>`, then run `hub ingest git <ROOT>` again, and repeat until no such warning remains (raise `--limit` to take bigger bites).
