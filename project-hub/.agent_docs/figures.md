# Figures registry
Code: `hub/figures.py` (`add_figure`, `sync_figures`, `stale_figures`, `render_gallery`, `write_gallery`, `FigureError`), CLI in `hub/cli_ext.py`. Paths are `$ROOT/relative/path` (ROOT is a key of `roots`; see vault-layout.md).
A figure is produced by the project's own scripts somewhere under a root. The vault keeps a copy so it can be read in Obsidian, plus the metadata needed to notice when the copy is out of date.
## Layout
- `Figures/<id>/figure.<ext>` — the copy (extension of the source, lower-cased). Generated; never hand-edit.
- `Figures/<id>/caption.md` — the caption. Written once at registration (`--caption`, else a placeholder comment) and never again by the tools. The human owns it.
- `Figures/<id>/meta.yaml` — metadata (below). Written by the tools.
- `Figures/Gallery.md` — generated by `hub figures sync` and `hub figures gallery`; never hand-edit.
- `<id>` is lowercase letters, digits and `-`, starting with a letter or digit (`phase-diagram`); anything else is a `FigureError`.
## meta.yaml keys
- `id`, `title` (shown in the gallery; empty means the id), `status` (`draft` at registration; `final` is set by hand), `licenses` (free text: the claim or section the figure supports)
- `source` — the figure file, `$ROOT/path`; `script` — the script that makes it (informational; empty allowed); `data` — list of data files or folders it is made from
- `figure_file` (name of the copy), `figure_hash` (hash of the source when last copied), `synced` (date of the last copy, null until the first re-copy)
- `data_hashes` — `{data entry: hash}` taken when the figure was last copied (a folder hashes its files); `changed_data` — entries whose hash now differs
- `stale` (bool) and `problem` (string or null) — the result of the last sync
## Sync rules (`hub figures sync`, per figure, in id order)
- source hash differs from `figure_hash`: the source is copied over the figure (atomically; a symlink at the target is never written through), a changed extension replaces the old file, `data_hashes` are re-taken, `changed_data` is cleared. Output `copied`.
- source unchanged: each data entry is re-hashed against `data_hashes`. Any difference puts the entry in `changed_data` and the figure is `STALE` (the data changed but the figure was not regenerated). An entry with no stored hash is recorded, not flagged. Nothing changed: `unchanged`.
- a problem is reported and the other figures still sync: the source is missing or not a file, a data path is missing, `meta.yaml` is unreadable or not a mapping. Output `PROBLEM: <why>`.
STALE is not a problem and does not change the exit code; regenerate the figure with its script, then sync again.
## CLI
- `hub figures add ID SOURCE [--title T] [--script S] [--data D]… [--licenses L] [--caption C]` — copy SOURCE into `Figures/ID/`, write caption.md and meta.yaml, print the directory. `--data` repeats. Errors (bad id, already registered, source missing or not a file, unknown root) print `error: …`, exit 1, and leave nothing behind.
- `hub figures sync` — one line per figure: `<id>  copied|unchanged|STALE|PROBLEM: <why>`; then rewrites `Figures/Gallery.md`. Exit 1 if any figure has a problem, else 0.
- `hub figures gallery` — rewrite `Figures/Gallery.md` only and print its path.
`hub validate` and the Snapshot are not affected; `stale_figures(root)` returns one message per stale or problem figure for skills that want to report them.
## Gallery.md format
`# Figures`, an italic generated-by line, then per figure `## <id> — <title> (<status>)`, an embed of the figure file and of `Figures/<id>/caption`, `*Supports:* <licenses>` when set, `*Source:* \`<source>\`` with ` · *script:* \`<script>\`` when set, then `**Problem:** …` or `**Stale:** …` when applicable. With no figures: `No figures registered yet (\`hub figures add\`).` Captions live in their own files so editing one never conflicts with regeneration.
## Example
```
hub figures add phase-diagram '$SRC/plots/phase.png' --title "Phase diagram" --script '$SRC/plots/phase.py' --data '$DATA/runs' --licenses "Section 3 claim"
hub figures sync
```
