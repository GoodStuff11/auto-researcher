# Vault layout, configuration and small state files
Code: `hub/config.py` (`find_root`, `load_config`, `HubConfig`), `hub/sync_state.py`, `hub/snapshot.py`.
## Directory tree (relative to the vault root, the directory holding `project.yaml`)
- `project.yaml` — shared configuration (committed)
- `hub.local.yaml` — per-user configuration (gitignored)
- `.gitattributes`, `.gitignore` — maintained by `hub commit` (see git-sync.md)
- `Status/Items/<ID>.md` — one file per item (item-format.md)
- `Status/Pending/<P-id>.md` — one file per staged proposal (pending-format.md)
- `Status/Meetings/<series>/<YYYY-MM-DD>.md` — meeting note written by `hub agenda read`
- `Status/Log/<YYYY-MM>.md` — append-only journal
- `Status/Snapshot.md` — generated, never hand-edited
- `Status/sync-state.yaml` — ingest watermarks, next meeting dates, flags
- `Agenda/<series>.draft.yaml`, `Agenda/<series>.xlsx`, `Agenda/archive/<series>/<YYYY-MM-DD>.xlsx` (agenda-workbook.md)
## project.yaml
Parsed by `load_config` (`hub/config.py:35`). Required top-level keys: `name`, `people`, `series`; a missing one raises `ConfigError`.
- `name` (string) — project name, shown in the Snapshot title
- `people` (mapping) — key = people key (the identifier used as item owner and entry author), value = mapping (e.g. `{name: Alice}`); the people key must contain no whitespace
- `series` (mapping) — key = meeting series name; value = mapping; the only key the code reads is `attendees` (list of people keys, printed in the meeting note)
- `sources` (mapping, optional) — passed through as `HubConfig.sources`; not interpreted by the core
- `roots` (mapping, optional) — name to path; merged with `roots` from `hub.local.yaml` (local wins)
## hub.local.yaml
- `me` (string) — your people key; must be a key of `people`, else `ConfigError`. Overridden by the environment variable `HUB_ME`. Required by every command that writes (entry author).
- `roots` (mapping, optional) — local paths, merged over `project.yaml` `roots`
## Status/Log/<YYYY-MM>.md
First line `# Log YYYY-MM`, then one line per event in the item entry format `- YYYY-MM-DD · <author> · <source> — <text>` (see item-format.md). Written only by `Store.log` (`hub/store.py`, `hub log`, apply/reject of proposals, agenda read-back). Merges with git's union driver.
## Status/sync-state.yaml
Read/written by `load_state`/`save_state` (`hub/sync_state.py`); CLI `hub sync-state get SOURCE` / `set SOURCE VALUE` touches only `watermarks`. Missing keys default as shown.
- `watermarks` (mapping, default `{}`) — ingest source name to an opaque string (typically an ISO timestamp or last meeting id)
- `next_meeting` (mapping, default `{}`) — series name to a date (YAML date); shown in the Snapshot meetings table
- `flags` (list of strings, default `[]`) — unresolved sync problems, listed under `## Flags` in the Snapshot
## Status/Meetings/<series>/<YYYY-MM-DD>.md
Written by `read_agenda` (`hub/agenda/lifecycle.py`). Lines: `# <series> — <date>`, `- attendees: <keys>`, `- source: agenda:<series>/<date>`, then sections `## Decisions` (`- [[<id>]] <outcome> — <text>`), `## Not reached` (`- [[<id>]]`), `## Staged for approval` (`- <P-id> · <title>`); an empty section holds `None.`. Its existence also marks the meeting as read (a second read-back is refused while it exists). `last_meeting(root, series, before=)` (`hub/snapshot.py:14`) takes the latest file stem that parses as a date.
## Status/Snapshot.md
Generated by `hub snapshot` (`render_snapshot`, `hub/snapshot.py:29`). Sections in order: `# Snapshot — <name>`, `## Meetings` (table Series, Last meeting, Next meeting), `## Open questions (n)` (open questions sorted by priority then raised date; columns ID, Title, Owner, Age (d), Priority), `## Proposed decisions (n)`, `## Open actions (n)` (grouped under `### <owner>` or `### unassigned`, sorted by due date), `## Flags`, `## Validation` (`<n> issues.`). Regenerated by `hub commit`; on merge the upstream copy wins and is then regenerated.
