# R51.28 — blocked or Kronecker-factored metric to cut the effective rank (blockrank) (KILLED)
* **The idea**: Replace the full parameter metric $S$ in SR by a block-diagonal (per layer, per orbital column of the backflow output) or Kronecker-factored (K-FAC) approximation. Each block has far fewer parameters than the whole, so it is estimated from fewer samples; if the samples needed per step track the metric's effective rank rather than the number of configurations the state occupies, a lower-rank geometry would turn the support-like growth into a polynomial one.
* **Lineage**: round 16 batch, orchestrator's direction (a); same family as P4.1 R32 (two-stage blocked SR, killed) and K-FAC (Analogy Map B1, killed there).
* **Outcome**: KILLED at T0 (2026-11-18).
* **Kill rule**: T0: is the premise (need tracks effective rank) supported on these states, and did blocking help where it was measured?
* **Evidence**: (i) R51.10 measured the ridge noise-to-signal ratio $\kappa$ (effective dimension × residual variance / signal) exactly at the R51.8 starts: ×0.70 from 10 to 12 sites, while the multi-step need grew ×3.79; at the exact arms' endpoints $\kappa_{\rm guided}$ is 10.5k (5×2) and 1.89M (6×2), ×180 (`tests/P5.1_vr_r12/results/vr_S*_end.json`). Neither tracks the need, so no rank-based quantity is known to set it. (ii) P4.1 R32 (12 sites, 16,384 draws, 3 seeds): block-diagonal one-step gain −0.002 ± 0.008, two-stage blocked −0.007 ± 0.005, plain 0.016 ± 0.022; exact metric with sampled force −0.024 ± 0.011, exact force with sampled metric +0.171 (L59): the metric is not where the noise is.
* **Why this kills it**: a metric approximation changes only the $S$ side, and at these sample sizes the force side carries the error (L59); the rank premise that would make a cheaper metric shrink the need is contradicted by both $\kappa$ measurements.
* **What the kill does not rule out**: blocking as a memory device at large $P$; a geometry change that also filters the force by its noise level (R51.26).
* **Strongest case against the kill**: R32 is one step at one start; a blocked metric changes the noise-free path too, so a multi-step need against its own noise-free run is untested. Answered in part: its noise-free path is a worse optimiser (it drops inter-block curvature), and R51.26 tests the force-side version of the same idea.
* **Checked by**: not yet reviewed (worker gate, round 16).
* **Lesson**: L59 (force noise dominates); proposed extension: the need tracks neither start nor end $\kappa$.
