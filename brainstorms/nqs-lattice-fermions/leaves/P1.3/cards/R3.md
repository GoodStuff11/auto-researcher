# R3 — Sign-flip-aware Metropolis moves (round-1 Route 3) (KILLED)
* **The idea**: Change the Monte Carlo sampler, adding proposals such as pair hops or exchange moves biased toward sign changes, so that sampling crosses nodal regions and the optimiser sees the configurations whose signs are wrong. It was expected to help if sampling, not optimisation, kept the network in a wrong-sign basin.
* **Lineage**: initial batch (round 1). Not mutated.
* **Outcome**: KILLED at G1 (2026-11-10).
* **Kill rule**: Gate 1: does the route violate a structural property of the method? Here: can a sampler change which stationary point SR converges to?
* **Evidence**: On a discrete lattice, Metropolis sampling of $\lvert\psi\rvert^2$ jumps between configurations and never visits the zero-amplitude points between them, so nodes do not confine it. The SR update is a function of expectation values, so in the infinite-sample limit its fixed points do not depend on the sampler. The decisive tests used exact sums, with no sampler at all.
* **Why this kills it**: A sampler change alters only the noise of the expectation values, not the flow they define, so it cannot change which basin is reached.
* **What the kill does not rule out**: noise-driven escape at finite sample size, where the sampler shapes the noise (that is the tempering idea R7.5); variance reduction as an efficiency gain.
* **Strongest case against the kill**: finite-sample SR noise could kick the state between basins, and a sampler shapes that noise (not raised by a critic). Answered indirectly: the tempering version R7.5 was killed because no probed instance had a better basin to escape to.
