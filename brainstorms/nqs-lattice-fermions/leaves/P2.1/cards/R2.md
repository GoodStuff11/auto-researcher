# R2 — Readout-rank exact ratios for transformer backflow (Route 2) (KILLED)
* **The idea**: In transformer backflow each orbital row is a fixed orbital plus a token embedding $t_x\in\mathbb{R}^d$ times a readout matrix, so the change of the whole matrix under any hop has rank at most $d+1$. With the readout times the inverse cached, every ratio is a $(d+1)$-dimensional determinant, exact, with no change to the family.
* **Lineage**: initial batch (round 1).
* **Outcome**: KILLED at G1 (2026-11-10).
* **Kill rule**: Gate 1: does the claimed cost survive the full operation count, including the network forward pass per connected configuration?
* **Evidence**: one changed token changes every token after the first attention layer, so each of the $\mathcal{O}(zN_e)$ connected configurations needs a forward pass of cost $\Theta(V^2d)$, giving $C_E=\Theta(N_e^3d)$. In the published run (Gu et al., arXiv:2507.02644) $d=256\ge N_e=224$, so the rank bound is vacuous as well.
* **Why this kills it**: the determinant algebra is no longer the bottleneck; the forward pass alone is at least cubic, which is the barrier the leaf exists to remove (F1, P3).
* **What the kill does not rule out**: attention variants whose per-hop forward change is local or low-rank; R7.4 tried the linear-attention version.
* **Strongest case against the kill**: a cached key-value forward could cut the forward cost; not raised by a critic; answered by the fact that in a multi-layer transformer every later-layer token depends on the changed token, so caching does not avoid recomputing $\mathcal{O}(V)$ tokens.
* **Checked by**: round-1 per-leaf critic (2026-11-11).
* **Lesson**: route-specific — the attention forward pass, not the determinant, sets the cost.
