# R6.3 — Translation-equivariant trunk with shared image tables (Route 6.3) (KILLED)
* **The idea**: With a translation-equivariant sign trunk, the network outputs for all symmetry images of a configuration are permutations of one forward pass, so symmetry projection would need no extra network evaluations and only extra carried tables per image.
* **Lineage**: Operation A on R3.3 (round 6).
* **Outcome**: KILLED at G4 (2026-11-16, T0).
* **Kill rule**: Gate 4: does the gain survive system size, or is it a finite-size bonus?
* **Evidence**: the carried tables are still one set per image, so $C_E=\mathcal{O}(\lvert G\rvert N_e^2)$, which is cubic with translations ($\lvert G\rvert\propto V$); with the point group only, the gain is one global quantum number worth $\mathcal{O}(1/V)$ per site, and a fully equivariant ansatz with an invariant reference is already symmetric.
* **Why this kills it**: either the cost is cubic or the accuracy gain vanishes per site.
* **What the kill does not rule out**: point-group projection as an ED-size accuracy tool.
* **Strongest case against the kill**: none raised.
* **Checked by**: round-6 per-leaf critic (2026-11-16).
